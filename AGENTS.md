# word-vault — Agent Guide

## Quick start

```bash
npm install
# Run BOTH API server and Vite:
node scripts/dev.mjs
# Or run them in separate terminals:
npm run dev          # Vite dev server @ http://127.0.0.1:5173
node server/index.mjs # API server @ http://127.0.0.1:4174
```

Build (typecheck + bundle):
```bash
npm run build        # tsc && vite build
npm run preview      # Vite preview (requires built dist/)
```

Chrome Extension (build + icons):
```bash
npm run ext          # generate icons + build → dist/ is loadable as unpacked extension
npm run ext:dev      # dev build + icons
```

## Chrome Extension

The app is also packaged as a **Chrome Extension** (Manifest V3).

| File | Purpose |
|---|---|
| `public/manifest.json` | Extension manifest — side panel, context menus, host permissions |
| `public/background.js` | Service worker — side panel lifecycle, right-click "添加到生词库" |
| `public/icon*.png` | Extension icons (auto-generated by `scripts/generate-icons.mjs`) |
| `src/api.ts` | Auto-detects extension context → uses `translate-word-vault.vercel.app` API |

### How it works

1. **`npm run ext`** builds the app + copies icons + manifest + background script into `dist/`
2. Load `dist/` in Chrome: **Extensions → Load unpacked → select `dist/`**
3. The side panel opens when you click the extension icon
4. **Right-click any selected text** → "添加到生词库" → opens side panel with text pre-filled
5. All data is synced with your remote Vercel API (`translate-word-vault.vercel.app`)

### Features

- **Side Panel**: Click toolbar icon or press `Ctrl+B` (Cmd+B) — lives in Chrome's right sidebar
- **Right-click add**: Select text → right-click → "添加 "%s" 到术语库"
- **Quick lookup**: Select text → right-click → "查询 "%s"" — opens panel with search pre-filled
- The side panel auto-fills the query from the context menu (get-prefill / clear-prefill messages); the topbar shows no special badge

## Architecture

Single-page dictionary app (English ↔ Chinese). Persistence via **`@libsql/client`** — local `file:` SQLite for dev, remote Turso for Vercel deployment.

```
scripts/dev.mjs      # spawns both servers concurrently
server/index.mjs     # Node.js HTTP API server, serves static dist/
server/whiteboard.mjs # Whiteboard feature module (standalone, removable)
api/index.mjs        # Vercel serverless function entry (re-exports server handler)
src/                 # Vite React frontend
src/whiteboard/      # Whiteboard feature folder (standalone, removable)
abbrs.md             # bundled seed vocabulary
data/dictionary.sqlite # auto-created SQLite DB (local dev)
vercel.json          # Vercel build config + function routing
```

## Bulk word import

`scripts/import-words.mjs` (alias `npm run words`) reads a plain-text word list (default `abbr-new.txt`) and inserts entries into the Turso DB configured in `.env.local`.

| Line form | Handling |
|---|---|
| `forgo, 放弃` | English + Chinese on one line → used as-is, no LLM call |
| `decomposition` | English only → LLM translates to Chinese (`en-to-zh`) |
| `分解` | Chinese only → LLM translates to English (`zh-to-en`) |
| `forgo, distinction` | Comma list of same-language words → split into separate entries |

- Flags: `--dry-run` (translate + preview only), `--verbose` (print the full LLM payload)
- Dedupes on `source_text` (case-insensitive) — existing rows are skipped, never overwritten
- Writes core fields only: `source_text`, `target_text`, `direction`, `note`, `tags` (`["abbr-new"]`), timestamps
- Key resolution: `LLM_API_KEY`, falling back to a `DEEPSEEK_API_KEY` shell env var on 401/403; reuses the `/api/lookup` translation prompt

## Print export

`scripts/export-words.mjs` (alias `npm run export`) dumps TermVault to a plain-text file for printing.

- **Fixed output**: `data/termvault.txt` (gitignored, auto-created). Override with `--out <path>`
- **Always a full regenerate**: the file is written to a temp file then renamed over the target, so repeated runs never append and never duplicate
- **Source**: Turso when `TURSO_DATABASE_URL` is set in `.env.local`, else the local `data/dictionary.sqlite`
- **Format**: alphabetically sorted (`localeCompare` en + zh-Hans), one entry per line as `source — target`, with a header showing time + count
- Flags: `--all` (include archived), `--starred` (only starred), `--group` (A–Z / # / 其他 section headers), `--notes` (note on a second line)
- Dedupes on the lowercased `(source, target)` pair and reports skipped archived / duplicate / non-starred counts

## Whiteboard (白板便签) — standalone feature

A small notepad separate from TermVault: click the notebook icon in the topbar to open it. Notes support add / inline edit / delete / move up-down, rendered as `ul/li` list items.

- **Own table**: `wb_notes` (id, title, content, position, created_at, updated_at) — never touches the `entries` table
- **Own routes**: `/api/whiteboard/notes` (GET list, POST create) and `/:id` (PUT edit, PATCH move, DELETE)
- **Own files**: `server/whiteboard.mjs` + `src/whiteboard/` (types.ts, api.ts, Whiteboard.tsx)
- **To remove entirely**: delete `server/whiteboard.mjs` and `src/whiteboard/`, drop the `wb_notes` table, then remove the marked lines in `server/index.mjs` (import + `initWhiteboardSchema` call + route dispatch), `src/App.tsx` (import, state, topbar icon, overlay mount) and the `Whiteboard` CSS block in `src/styles.css`

| Dir | Purpose |
|---|---|
| `src/` | React app — main sources + styles.css + `whiteboard/` |
| `server/` | Single-file Node.js HTTP + SQLite API |
| `api/` | Vercel serverless function entry point |
| `scripts/` | Dev orchestrator (spawns both processes); `import-words.mjs` imports a word list into Turso; `export-words.mjs` exports entries to a printable txt |
| `dist/` | Build output (gitignored) |
| `data/` | SQLite database (auto-created, gitignored) |

## API routes

All routes are prefixed with `/api/`:

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/entries` | — | `{ entries: [...] }` |
| POST | `/api/entries` | `{ sourceText, targetText, direction, note, tags }` | `{ entry: {...} }` |
| PUT | `/api/entries/:id` | full entry fields | `{ entry: {...} }` |
| PATCH | `/api/entries/:id` | `{ archived: bool }` (partial) | `{ entry: {...} }` |
| DELETE | `/api/entries/:id` | — | `{ ok: true }` |
| POST | `/api/import/abbrs` | `{}` | `{ added: N, entries: [...] }` |
| POST | `/api/import/json` | `{ entries: [...] }` | `{ added: N, entries: [...] }` |
| POST | `/api/lookup` | `{ word }` | `{ translation, meanings, synonyms, antonyms, examples, direction }` |

Whiteboard routes (standalone feature):

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/whiteboard/notes` | — | `{ notes: [...] }` ordered by position |
| POST | `/api/whiteboard/notes` | `{ title, content }` | `{ note: {...} }` |
| PUT | `/api/whiteboard/notes/:id` | `{ title, content }` | `{ note: {...} }` |
| PATCH | `/api/whiteboard/notes/:id` | `{ move: "up" \| "down" }` | `{ note: {...} }` |
| DELETE | `/api/whiteboard/notes/:id` | — | `{ ok: true }` |

## Key facts

- **No linter, no formatter, no test framework** — don't add them without discussion
- **TypeScript strict mode** is on; prefer avoiding `as any` and `@ts-ignore`
- **Tags** are stored as JSON array strings in SQLite (`tags TEXT DEFAULT '[]'`); parsed on read
- **Entries have a unique constraint** on `(lower(trim(source_text)), lower(trim(target_text)))`
- **Direction** is `"en-to-zh"` or `"zh-to-en"` (SQLite CHECK constraint); the lookup route guesses it from the word's script (entries are always saved with a concrete direction — `auto` is never stored)
- **Import merges by text pair** — if source+target match, the entry is skipped (not duplicated)
- **Database path** is `data/dictionary.sqlite`; override via `DICTIONARY_DB_PATH` env var
- **Port** defaults to 4174 for API, 5173 for Vite; override via `PORT` env var (API server only)
- **Auto-seed**: `abbrs.md` is imported automatically on first server start (tracked in `metadata` table)
- **No SSR, no routing** — single-page app, all state in React component
- **`@libsql/client`** replaces `node:sqlite` — uses `file:` protocol for local dev, Turso for Vercel (set `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN`)
- **Node.js 18+** required (for `@libsql/client`); Vercel function uses Node.js 22
- **Vite proxies `/api/*`** to port 4174 in dev mode (configured in `vite.config.ts`). In production, the API server serves static `dist/` directly on the API port, no proxy needed.
- **`data/` is gitignored** — the SQLite database is auto-created and should not be committed.
- **Search is strict substring matching** over source text, translation, note, tags, synonyms, antonyms, and direction (no fuzzy subsequence matching). A non-existent query shows an empty state with 自动添加（AI 翻译）, which runs the LLM lookup and offers 保存.
- **Pronunciation (朗读)** uses the browser's built-in `window.speechSynthesis` (Web Speech API) — no key, no network request, no new dependency. `speakWord` in `src/App.tsx` cancels the previous utterance, sets `lang="en-US"` and `rate = 0.9`, and picks the voice via `pickEnglishVoice`. **Do not use "first en-US voice"**: macOS ships novelty voices (`Ralph`, `Albert`, `Bubbles`, `Zarvox`, `Trinoids`…) that report `en-US` and Chrome lists them first, so `pickEnglishVoice` tries a name preference list (`PREFERRED_ENGLISH_VOICES`: `Samantha`, `Ava`, `Karen`…), skips `NOVELTY_VOICE_NAMES`, and matches on the bare name because macOS reports e.g. `Eddy (English (United States))`. `englishTextFor(entry)` decides what is read: the source text when it has no Chinese characters, otherwise the translation — so zh→en rows still speak English — and `spokenTextFor` strips a Chinese gloss (`Terraform（基础设施即代码工具）` → `Terraform`) plus leftover CJK, which an en-US voice would mangle. Voices load asynchronously; when `getVoices()` is still empty the `lang` attribute alone picks an English voice. The speaker button leads the five row actions, so `.tbl-row` needs `padding-right: 132px` to keep the icons clear of the translation column.
- **LLM translation guarantee**: English input must produce a Chinese `translation` (prompt-enforced); proper nouns/brand names keep the English name with a Chinese explanation in parentheses (Terraform → Terraform（基础设施即代码工具）). The frontend `translationFor` helper falls back to `meanings[0].text` when the model echoes the input in the same language — used by the preview flow and AI 重译.
- LLM 自动翻译走 OpenAI 兼容接口：LLM_API_KEY (必填), LLM_BASE_URL (默认 https://api.deepseek.com/v1), LLM_MODEL (默认 deepseek-chat)。服务端与 `scripts/import-words.mjs` 一样，在 LLM_API_KEY 被 401/403 拒绝时回退到 DEEPSEEK_API_KEY
- **换 LLM key 要同时改两处**：`.env.local` 和 Vercel 环境变量（Production **和** Preview），改完必须重新部署——Vercel 的环境变量在部署时注入。线上验证：`curl -X POST https://translate-word-vault.vercel.app/api/lookup -H 'Content-Type: application/json' -d '{"word":"backpressure"}'`
- `/api/lookup` 每次上游请求有 12s 超时（`LLM_TIMEOUT_MS`），key 被拒会 `console.warn`，最终失败会 `console.error`——排查时先看 Vercel runtime logs
- Vercel 上若未配 `TURSO_*`，`getDb()` 会退化到 `/tmp/dictionary.sqlite`（serverless 只有 /tmp 可写）；本地仍用 `data/dictionary.sqlite`

## Style conventions

- Custom CSS via `styles.css` (no Tailwind, no CSS-in-JS)
- Import icons from `lucide-react` by name
- API calls: async/await, try/catch, message strings in Chinese
- Import pattern: type imports via `import type`, grouped: React hooks → lucide-react → local modules
- Prefer single-file approach unless a module clearly warrants extraction
